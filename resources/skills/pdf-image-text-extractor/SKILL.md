# PDF 和图片文字提取（本地视觉模型）

## 简介

本 Skill 基于 DeepChat 内置的 `read` 工具与**本地已配置的视觉模型**完成文字提取。无需任何外部 API Key、鉴权服务或联网 OCR——模型与密钥全部由应用内的模型配置管理。

- 图片与扫描件识别：内置 `read` 工具调用本地视觉模型
- PDF 文字层：内置 PDF 解析器在本地完成提取
- 扫描页渲染：唯一的可选辅助脚本（纯本地库 pymupdf，不联网）

## 前置条件

1. **图片/扫描件识别**：当前会话模型支持视觉（vision），或在 **Agent 设置**中已配置视觉模型。未配置时 `read` 图片会返回 "Image analysis unavailable" 提示，此时应引导用户去配置，不要尝试用其他方式猜测文字。
2. **扫描页渲染脚本（可选）**：仅处理扫描版 PDF 时需要，依赖 `pymupdf`（纯本地 Python 库，无网络请求）：`pip install pymupdf`。
3. 无需任何 API Key。

## 核心工具

### read（内置工具）

| 输入类型 | 行为 |
|---|---|
| 图片（PNG/JPG/JPEG/GIF/WebP/BMP/TIFF） | 调用本地视觉模型分析图片，返回内容描述（含可辨认的文字） |
| PDF | 本地提取文字层，返回 Markdown 文本（多页以 `---` 分隔），不返回原始二进制 |
| 加密/损坏 PDF | 返回错误提示，此时告知用户即可，不要反复重试 |

注意：`read` 图片返回的是视觉模型的**分析描述**（英文、包含图中可辨认的文字），不是逐字 OCR 结果。转写中文内容时必须原样保留中文，不要翻译；描述性语句不要输出给用户。

### render_pdf_pages.py（可选本地脚本，仅扫描版 PDF 使用）

```bash
python "${SKILL_ROOT}/scripts/render_pdf_pages.py" <pdf_path> [选项]
```

| 选项 | 说明 |
|---|---|
| （默认） | 自动检测文字层稀少（< 20 字符）的页并渲染为 PNG |
| `--pages 1,3-5` | 只渲染指定页 |
| `--all` | 渲染全部页 |
| `--threshold N` | 扫描页判定阈值（默认 20 字符） |
| `--scan-dir DIR` | 图片输出目录（默认 `<pdf名>_ocr_pages/`） |
| `--dpi N` | 渲染分辨率（默认 200，越高越清晰） |

stdout 输出 JSON：`success` / `page_count` / `images`（`[{page, image}]`）/ `warnings` / `error`。脚本需要 pymupdf，报缺少依赖时提示用户 `pip install pymupdf`。

## 操作流程

### 图片文字提取

1. 用 `read` 读取图片文件路径
2. 从视觉分析中整理出所有文字内容（标题、正文、注释、水印等），转写为原文语言
3. 保持原有的结构与排版输出
4. **数字转写核对**：对手机号、订单号、金额、日期等关键数字串，依据字形特征核对易混字符：

   | 字符 | 关键视觉特征 |
   |------|-------------|
   | 8 | 上下两个封闭圆圈 |
   | 6 | 仅下方一个封闭圆圈，顶部向左弯弧 |
   | 9 | 仅上方一个封闭圆圈，底部向下竖线 |
   | 0 | 完整封闭椭圆，无开口 |
   | 3 | 右侧开口，两个弧形朝右 |
   | 5 | 顶部横线 + 左侧竖线 + 下方圆弧 |

   无法 100% 确认的字符标注 `[?]` 并给出 2 个备选，如 `158****8[?可能为6]624`
5. 未检测到文字 → 告知用户"图片中未包含可提取的文字"

### PDF 文字提取

1. 用 `read` 读取 PDF 路径，获得按页分隔的文字层 Markdown
2. 整理输出，保留段落结构与标题层级
3. 返回 "no extractable text layer"（整份为扫描版）→ 进入扫描版流程
4. 部分页面内容缺失（文字版与扫描页混合）→ 进入扫描版流程，渲染缺失页

### 扫描版 PDF

1. 运行渲染脚本（默认自动检测扫描页），解析 `images` 清单
2. 对每张 PNG 逐一用 `read` 识别
3. 把识别出的文字按页并入正文，并告知用户哪些页是扫描页
4. 未安装 pymupdf 时：提示用户执行 `pip install pymupdf` 后重试，不要尝试其他联网 OCR

### 表格内容提取

- `read` 对 PDF 表格只做近似文本提取（无结构化表格输出），需依据上下文与列对齐关系把数据重组为 Markdown 表格
- 复杂表格（合并单元格、嵌套）：建议用渲染脚本渲染该页，再 `read` 识别，按视觉布局重组表格
- 重组结果建议提示用户核对

### 批量目录处理

1. 用 `glob` 列出目录下所有 `*.pdf` 与图片文件（PNG/JPG/JPEG/GIF/WebP/BMP/TIFF）
2. 按文件名逐个处理：PDF → `read`；图片 → `read`；扫描版 → 渲染脚本 + `read`
3. 汇总统计：总文件数 / 成功数 / 失败数
4. 按用户要求合并输出为一个 `.md` 文件，或逐文件展示
5. 建议每次不超过 100 个文件

## 输出要求

- 默认直接在对话中输出提取结果
- 用户要求保存时生成 `.md` 文件：PDF 多页以 `---` 分隔，表格用 Markdown 表格
- 只输出提取到的文字内容，不要复述视觉分析的描述性语句

## 能力边界

- `read` 图片返回的是视觉模型分析（英文描述 + 可辨认文字），密集小字、长文档可能不完整，重要内容建议人工复核
- 不支持加密或受密码保护的 PDF
- 识别准确性受图片清晰度、字体、背景影响；文字模糊时说明情况并给出最佳识别结果
- 视觉分析不可用（未配置视觉模型）时明确告知用户，不要编造文字

## 故障排除

| 现象 | 处理 |
|---|---|
| `read` 图片返回 "Image analysis unavailable" | 当前会话模型不支持视觉且 Agent 未配置视觉模型，引导用户在设置中配置 |
| `read` PDF 返回 "no extractable text layer" | 扫描版 PDF，走扫描版流程（渲染脚本 + `read`） |
| 渲染脚本报缺少 pymupdf | 提示 `pip install pymupdf`（本地库、不联网） |
| 渲染脚本报无法打开 PDF | PDF 可能已加密或损坏，如实告知用户 |
